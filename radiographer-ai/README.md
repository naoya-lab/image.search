# 放射線技師AI v0.1 (教育・研究用)

既存 image.search を変更せず、別ディレクトリで試すMVPです。

## 内容
- `index.html`：iPhone/PC向け質問画面。テキストのみで画像のアップロードはありません。
- `worker/src/index.js`：Cloudflare Worker経由でLLMへ問い合わせ。APIキーはブラウザに渡しません。
- CT/CTA、MRI、一般撮影、透視、マンモグラフィ、画像物理・品質管理を選択できます。
- 回答は必ず技師・医師による確認が必要です。個別の診断・治療・撮影実施を自動決定しません。

## 展開手順（管理者）
1. Cloudflare Worker を `radiographer-ai/worker` からデプロイできる環境を用意。
2. Cloudflare で `OPENAI_API_KEY` を**Secret**として登録。GitHub、HTML、wrangler.tomlには絶対に置かない。
3. `AI_MODEL` をご自身の契約で利用可能なモデルIDに変更。現在の値は設定例です。
4. `ALLOWED_ORIGIN` を実際の画面配信元のオリジンに合わせる（GitHub Pages なら `https://naoya-lab.github.io`）。これはCORS設定に過ぎず**認証ではありません**。
5. **公開前に必須**：Cloudflare Access 等で API にサーバー側のアクセス制限を設置し、WAFのレート制限・費用上限・濫用監視を有効化。認証方式によってはフロントからの認証動作の追加実装が必要です。現コード単体で一般公開しないでください。
6. Worker APIが利用可能になったら `index.html` の「APIのURL」に `https://<worker>/api/ask` を入力します。URLはブラウザに保存されません。
7. まず架空症例で、個人情報保護・医療安全・出典の未確認表示をテストしてください。

## 非対応・制限（重要）
- RAG/文献検索、参照文献の自動照合、施設プロトコルDB、DICOM解析、熟練技師との比較試験、認証UI、サービス側監査/レート制限は未実装。
- 正規表現による患者情報検出は限定的で、匿名化を保証できません。**実患者情報を送信しない**こと。
- Workerから外部AIサービスへ質問文が送られます。院内規定・データ取扱条件が許容する範囲に限定。
- AI応答は誤りや架空の根拠を含む可能性があり、臨床利用前の第三者評価が必須。
- 本版は医療機器認証・承認を取得したものではありません。想定する用途に応じて日本の規制への該当性を確認してください。

## MVPの受け入れ試験
- 未設定API URLで通信しない
- HTTPS以外のAPI URLを拒否
- 非許可Originを403にする（ただしOriginだけでは認証不可）
- 入力3000字を超えると拒否
- APIキーを画面ソースに含めない
- 応答に根拠の確認状況・不確実性がある
- 画像や個人情報を入力しない運用ができる
